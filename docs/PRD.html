1. 产品定义

1.1 一句话

Quicklet 是一个 macOS 菜单栏工具，让用户用 shell 脚本定义 Finder 右键菜单项，

并且只在「选中的东西符合条件」时才出现。

1.2 要解决的问题

macOS 的 Finder 右键菜单二十年没什么变化。用户每天重复的动作——在终端打开当前目录、

复制文件路径、新建一个 Markdown 文件、把图片批量转 WebP、把选中的几个文件压成一个包——

要么走「打开 App → 拖文件 → 点菜单」，要么记一条终端命令再手动粘贴路径。

现有工具解决了一部分，但都停在半路：

  • 功能集合型（iRightMouse、MouseBoost、Supercharge）把几十个固定动作塞进右键菜单。

覆盖了高频场景，但用户自己的流程无法表达；菜单越来越长，不能按上下文收缩。

  • 单一功能型（New File Menu、Easy New File、RClick）只补一个洞。
  • 可编程型（FileMenu Tools、Nautilus Scripts、Raycast Script Commands）证明了

「用户写脚本 + 变量注入」是最有生命力的模型，但 macOS 上要么没有对应产品，

要么只是一个附带功能（MouseBoost 的脚本入口），要么过于简陋（Finder Actions 不能设条件、

不能分组、没有参数）。

  • Apple 原生（Automator 快速操作 / 快捷指令）能力够，但入口在二级「服务」菜单里，

配置体验重，且改一个参数要回到快捷指令 App。

空白就在这里：macOS 缺一个「可编程 + 上下文感知 + 可分享」的右键菜单。

1.3 三条产品支柱

支柱含义判断标准（做不做某个功能时问自己）
可编程命令是脚本，不是勾选项。用户能表达工具作者没想到的流程这个需求能不能用「让用户写脚本」解决？能，就不做内置功能
上下文感知只在合适的时候出现：选中类型、扩展名、数量、路径、修饰键菜单项是否因为条件不符被藏起来？藏得对不对？
可分享一条命令是一个可读的文件，能导出、导入、进 dotfiles、发给同事用户能不能把这条命令给别人？

1.4 设计原则

  1. 菜单是一等公民，窗口不是。 用户 99% 的时间在 Finder 里，设置窗口只在配置时出现。

任何需要「先打开 App 再操作」的流程都算设计失败。

  1. 宁可少显示，不要显示错。 条件不满足就不出现。菜单里出现一条点下去报错的命令，

比它不出现伤害大得多。

  1. 默认安静。 不弹无关对话框、不做启动弹窗、失败不打断工作（走通知中心 + 日志）。
  2. 原生长相。 SF Symbols、系统强调色、系统控件。不做自绘皮肤，不抢 Finder 的视觉。
  3. 破坏性操作要留痕。 能撤销的走废纸篓，不能撤销的在执行前给出可读的脚本预览。

1.5 目标用户

P1 · 开发者「阿哲」（首要）

  • 30 岁，全栈，MacBook Pro，日常 8 小时在 VS Code / 终端 / Finder 之间跳。
  • 已经有一堆 shell alias 和脚本片段，散落在 .zshrc、~/bin、笔记里。
  • 痛点：cd 到某个深层目录再敲命令，每次都要复制路径；同事发来的脚本要手动改路径。
  • 要的东西：一条命令写好，右键就能用；能导出给同事；菜单里只出现当前场景该有的项。

P2 · 效率工具爱好者「小林」

  • 25 岁，产品经理，装了一堆效率 App，愿意为顺手的工具付费。
  • 不会写脚本，但会改别人写好的脚本（改个参数、换个 App 名）。
  • 痛点：菜单太长的工具用两天就烦；想要「新建文件」这类固定动作但不想为一个动作装一个 App。
  • 要的东西：开箱有 10 条好用的模板；能看懂脚本在干什么；能一键关掉不用的。

P3 · 团队里的「布道者」

  • 给 5 人小组统一一套右键动作（提交规范、打包、上传测试包）。
  • 痛点：口头描述 + 截图传脚本，版本对不上。
  • 要的东西：导出成一个文件，别人双击导入即用；能看到这条命令是谁写的、做什么。

1.6 非目标（明确不做）

不做原因
文件管理器 / 双栏 Commander和 Finder 抢活，做不过
内置几十个固定功能（哈希、转图、二维码…）那是 iRightMouse 的路线；Quicklet 用模板 + 脚本覆盖
云同步命令库（v1–v2）隐私与账号体系成本高；先做文件级导入导出
Windows / Linux 版本Finder Sync 是 macOS 独有，跨平台等于重写
宏录制 / 可视化流程编排与「脚本优先」冲突，且让产品变重
Mac App Store 上架沙箱不允许执行任意 shell，与产品核心冲突（详见 11.4）

2.2 逐个拆解：抄什么、不抄什么

iRightMouse（超级右键）

  • 抄：首批模板清单。它的功能列表就是中文用户的高频动作集，直接把前 10 名做成 Quicklet 模板

（新建文件、复制路径、终端打开、压缩、AirDrop、彻底删除、隐藏文件、哈希、转图、剪切粘贴）。

  • 抄：「常用目录」的心智——用户想把「跳到某个目录」变成一次点击，Quicklet 用 open {dir} 类模板覆盖。
  • 不抄：功能越堆越多的菜单。它自己的用户评价里就有「菜单太长建议自行配置」的抱怨，

这正是 Quicklet 用条件显示要解决的问题。

MouseBoost

  • 抄：脚本 + 内置动作混排的可行性验证；专业版 ¥30 说明这个品类有付费意愿。
  • 不抄：脚本只是一个「高级入口」。Quicklet 把脚本当唯一入口，把所有配置围绕它组织。

Supercharge / Shortcutie

  • 抄：原生长相和克制的交互（一个菜单栏图标、一个设置窗口、不弹窗）。
  • 抄：「只在需要的时候出现」的思路（它的动作按文件类型有条件）。
  • 不抄：把能力锁在作者提供的动作里。它的用户要新动作只能去写快捷指令，链路太长。

Finder Actions（开源）

  • 抄：极简的配置流（选择功能 → 排序 → 设显示位置），以及「不需要常驻窗口」的形态。
  • 抄：目录白名单思路，扩展为 Quicklet 的路径条件。
  • 不抄：用文件名/注释当元数据（对非技术用户不友好），Quicklet 用结构化配置 + GUI 编辑器。

FileMenu Tools（Windows，最重要的对标）

这是 Quicklet 功能模型的直接来源。它的自定义命令有这么几个属性，全部值得移植：

FileMenu Tools 属性Quicklet 对应
Element Types（文件扩展名通配 / 文件夹模式 / 驱动器类型）适用条件：选中类型 + 扩展名通配
Number of elements（最少 / 最多）适用条件：选中数量区间
Modifier Key（按住某键才显示）适用条件：修饰键（v1.2）
Arguments / Working folder占位符 + 工作目录字段
变量 %FILEPATHS% %FILEPATH1%占位符 {paths} {path}
导出/导入配置.quicklet 导出导入（v1.2）
按名称/类型/时间/大小排序后再执行选中项排序策略（v2）
多实例 / 管理员运行不做（macOS 无对应概念，提权走 sudo 由用户自担）

Raycast Script Commands

  • 抄：元数据驱动的命令定义——一个命令的全部信息（标题、图标、说明、参数、工作目录、

是否需要确认）都在一处声明；Quicklet 用 JSON 字段 + GUI 表单实现同一件事。

  • 抄：typed 参数（text / dropdown / password）与「最多 3 个」的克制，作为 v2 的参数模型。
  • 抄：退出码即失败，失败消息取 stderr 最后一行——Quicklet 的执行反馈直接采用这个约定。
  • 抄：needsConfirmation，对应 Quicklet 的「执行前确认」开关。
  • 不抄：Non-login shell 导致 PATH 缺失的坑（见 9.5 环境变量规格，Quicklet 主动修好 PATH）。

Automator / 快捷指令

  • 抄：「快速操作」的分享形态——用户已经理解「下载一个动作 → 装进系统 → 右键可用」。
  • 不抄：把配置放在另一个 App 里。Quicklet 的编辑器就是配置的唯一入口。

2.3 差异化定位

                可编程性 高
                     ▲
        Raycast      │      Quicklet
      (不在右键里)    │   (右键 + 条件 + 可分享)
                     │

一句话：iRightMouse 给你一堆功能，Quicklet 给你一个能长出任何功能的菜单。

2.4 从竞品得到的七个必须做的功能

这一节是第 5 章功能规格的来源，评审时先看这里：

  1. 适用条件（FileMenu Tools）：类型 / 扩展名 / 数量 / 路径。
  2. 占位符 + 环境变量（FileMenu Tools、Nautilus Scripts）：脚本拿到选择的方式要稳定、够用。
  3. 执行反馈（Raycast）：退出码、stderr、失败通知，不能"点了没反应"。
  4. 参数输入（Raycast）：v1 单行，v2 多参数 typed。
  5. 模板库（iRightMouse）：让不会写脚本的人第一天就有获得感。
  6. 导出/导入（FileMenu Tools、快捷指令）：命令能离开这台机器。
  7. 克制的默认外观（Supercharge）：菜单栏一个图标，一个设置窗口。

4. 产品结构与概念模型

4.1 概念模型

Command（命令）── 一条菜单项
├── 身份：id(UUID) · name · icon(SF Symbol) · enabled
├── 行为：script · shell · workingDirectory · timeoutSeconds
├── 输入：prompt（v1 单行输入）→ parameters（v2 多参数）
├── 位置：placement { topLevel | group([String]) } · order
├── 条件：conditions { selection · extensions · itemCount · paths · modifierKey }
└── 反馈：notifyOnFailure · showOutputWindow

四个关键词：

  • Command 是唯一实体。分组不是实体，只是命令上的一个路径（group: ["开发","Git"]），

同名路径自动合并成同一个菜单。

  • Placement 只有两种：右键第一层，或 Quicklet 根菜单下的 0–2 层分组。

Quicklet 根菜单名固定、不可删。

  • Conditions 是"何时可见"的谓词集合，全部满足才显示（AND 语义）。
  • Preset 是预填好的 Command 模板，创建后就是普通 Command，不与模板保持关联

（避免"改模板影响所有人"的隐式耦合）。

4.2 菜单结构（唯一合法形态）

Finder 右键
├── [第一层命令 A]                 ← placement = topLevel
├── [第一层命令 B]
├── ──────────
├── Quicklet                      ← 固定根菜单，永远存在
│   ├── [根下命令]                 ← group = [] 但 placement = root（v1.1 支持）
│   ├── 开发                       ← group = ["开发"]
│   │   ├── [命令]
│   │   └── Git                    ← group = ["开发","Git"]
│   │       └── [命令]

F5 适用条件（核心待实现） ⬜

目标：菜单只在「选中的东西符合条件」时出现。这是与功能集合型工具的分水岭。

条件字段

字段类型语义默认
selectionenumany / file / folder / mixed / noneany
extensions[String]扩展名，小写，支持 *；空数组＝不限[]
minItemsInt最少选中数（含）0
maxItemsInt最多选中数（含）；0＝不限0
pathPrefixes[String]选中项路径必须以其中之一开头（支持 ~）；空＝不限[]
excludePathPrefixes[String]命中即不显示（优先级高于 include）[]
modifierKeyenumnone / option / control / shift（按住才显示）none

语义

  • 多个字段之间是 AND；同一字段内多个值是 OR。
  • selection = none 表示「空白处右键（无选中）」；此时 dir 是当前浏览的文件夹。
  • 选中项类型不一致时：全部文件＝file，全部文件夹＝folder，混合＝mixed。

条件写 file 时 mixed 不匹配（宁可少显示）。

  • 路径前缀比较基于标准化后的绝对路径（~ 展开、去掉末尾 /），大小写敏感

（macOS 默认文件系统大小写不敏感，但 /Volumes 外置盘可能敏感，按字面比较更可预期）。

  • modifierKey 只在菜单构建时读取当前修饰键状态；不满足则该命令不出现。

规格

编号要求
F5-1编辑器「显示条件」区块，默认折叠为一行摘要：选中文件夹 · 1 项 · 任意路径
F5-2扩展名输入支持逗号分隔与标签式输入，自动补 .、转小写
F5-3提供「用当前 Finder 选择测试」按钮（v1.1 可只做静态提示文案）
F5-4条件不匹配的命令在设置列表中显示原因（灰色小字：当前不匹配：需要选中图片）
F5-5条件解析逻辑放在 Shared/CommandFilter.swift，纯函数、可单测、不依赖 Finder
F5-6配置里非法值（未知 enum、负数）回退默认并写日志，不让整个配置解码失败

验收

  • E1：命令条件 selection=folder，选中 2 个文件时该命令不出现；选中 1 个文件夹时出现。
  • E2：条件 extensions=["png","jpg"]，选中 a.png 出现；选中 a.txt 不出现；选中 a.png+b.txt 不出现（不是全匹配）。
  • E3：条件 minItems=2, maxItems=3，1/4/5 项时不出现，2/3 项时出现。
  • E4：条件 pathPrefixes=["~/work"]，在 ~/work/x 出现，在 ~/tmp 不出现。
  • E5：selection=none 的命令只在该文件夹空白处右键时出现。
  • E6：modifierKey=option，不按 ⌥ 不出现，按住 ⌥ 出现。

8. 技术架构与约束

8.1 现有链路

Finder 右键
  └─ QuickletFinder.appex（沙箱，不能 spawn 子进程）
       ├─ 读 commands.json（App Group）
       ├─ 构建 MenuTree → NSMenu
       └─ quicklet://run?id=<UUID>&path=…（URL scheme 传话）

14.3 术语

术语定义
命令（Command）一条右键菜单项及其脚本、位置、条件
占位符（Placeholder）脚本里被替换为路径/输入的 {…} token
条件（Condition）决定命令是否显示的谓词集合，AND 语义
位置（Placement）topLevel / root / group 三档
传话（Hand-off）扩展通过 URL 把命令 id 与路径交给主 App 的过程
模板（Preset）预填内容的命令草稿，创建后与模板无关
命令包（.quicklet）可导入导出的命令交换文件
