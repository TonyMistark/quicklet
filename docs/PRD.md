## 1. 产品定义

### 1.1 一句话

Quicklet 是一个 macOS 菜单栏工具，让用户用 shell 脚本定义 Finder 右键菜单项，
并且只在「选中的东西符合条件」时才出现。

### 1.2 要解决的问题

macOS 的 Finder 右键菜单二十年没什么变化。用户每天重复的动作——在终端打开当前目录、
复制文件路径、新建一个 Markdown 文件、把图片批量转 WebP、把选中的几个文件压成一个包——
要么走「打开 App → 拖文件 → 点菜单」，要么记一条终端命令再手动粘贴路径。

现有工具解决了一部分，但都停在半路：

- **功能集合型**（iRightMouse、MouseBoost、Supercharge）把几十个固定动作塞进右键菜单。
  覆盖了高频场景，但**用户自己的流程无法表达**；菜单越来越长，不能按上下文收缩。
- **单一功能型**（New File Menu、Easy New File、RClick）只补一个洞。
- **可编程型**（FileMenu Tools、Nautilus Scripts、Raycast Script Commands）证明了
  「用户写脚本 + 变量注入」是最有生命力的模型，但 macOS 上要么没有对应产品，
  要么只是一个附带功能（MouseBoost 的脚本入口），要么过于简陋（Finder Actions 不能设条件、
  不能分组、没有参数）。
- **Apple 原生**（Automator 快速操作 / 快捷指令）能力够，但入口在二级「服务」菜单里，
  配置体验重，且改一个参数要回到快捷指令 App。

空白就在这里：**macOS 缺一个「可编程 + 上下文感知 + 可分享」的右键菜单**。

### 1.3 三条产品支柱

| 支柱 | 含义 | 判断标准（做不做某个功能时问自己） |
| --- | --- | --- |
| 可编程 | 命令是脚本，不是勾选项。用户能表达工具作者没想到的流程 | 这个需求能不能用「让用户写脚本」解决？能，就不做内置功能 |
| 上下文感知 | 只在合适的时候出现：选中类型、扩展名、数量、路径、修饰键 | 菜单项是否因为条件不符被藏起来？藏得对不对？ |
| 可分享 | 一条命令是一个可读的文件，能导出、导入、进 dotfiles、发给同事 | 用户能不能把这条命令给别人？ |

### 1.4 设计原则

1. **菜单是一等公民，窗口不是。** 用户 99% 的时间在 Finder 里，设置窗口只在配置时出现。
   任何需要「先打开 App 再操作」的流程都算设计失败。
2. **宁可少显示，不要显示错。** 条件不满足就不出现。菜单里出现一条点下去报错的命令，
   比它不出现伤害大得多。
3. **默认安静。** 不弹无关对话框、不做启动弹窗、失败不打断工作（走通知中心 + 日志）。
4. **原生长相。** SF Symbols、系统强调色、系统控件。不做自绘皮肤，不抢 Finder 的视觉。
5. **破坏性操作要留痕。** 能撤销的走废纸篓，不能撤销的在执行前给出可读的脚本预览。

### 1.5 目标用户

**P1 · 开发者「阿哲」**（首要）
- 30 岁，全栈，MacBook Pro，日常 8 小时在 VS Code / 终端 / Finder 之间跳。
- 已经有一堆 shell alias 和脚本片段，散落在 `.zshrc`、`~/bin`、笔记里。
- 痛点：`cd` 到某个深层目录再敲命令，每次都要复制路径；同事发来的脚本要手动改路径。
- 要的东西：一条命令写好，右键就能用；能导出给同事；菜单里只出现当前场景该有的项。

**P2 · 效率工具爱好者「小林」**
- 25 岁，产品经理，装了一堆效率 App，愿意为顺手的工具付费。
- 不会写脚本，但会改别人写好的脚本（改个参数、换个 App 名）。
- 痛点：菜单太长的工具用两天就烦；想要「新建文件」这类固定动作但不想为一个动作装一个 App。
- 要的东西：开箱有 10 条好用的模板；能看懂脚本在干什么；能一键关掉不用的。

**P3 · 团队里的「布道者」**
- 给 5 人小组统一一套右键动作（提交规范、打包、上传测试包）。
- 痛点：口头描述 + 截图传脚本，版本对不上。
- 要的东西：导出成一个文件，别人双击导入即用；能看到这条命令是谁写的、做什么。

### 1.6 非目标（明确不做）

| 不做 | 原因 |
| --- | --- |
| 文件管理器 / 双栏 Commander | 和 Finder 抢活，做不过 |
| 内置几十个固定功能（哈希、转图、二维码…） | 那是 iRightMouse 的路线；Quicklet 用模板 + 脚本覆盖 |
| 云同步命令库（v1–v2） | 隐私与账号体系成本高；先做文件级导入导出 |
| Windows / Linux 版本 | Finder Sync 是 macOS 独有，跨平台等于重写 |
| 宏录制 / 可视化流程编排 | 与「脚本优先」冲突，且让产品变重 |
| Mac App Store 上架 | 沙箱不允许执行任意 shell，与产品核心冲突（详见 11.4） |

### 2.2 逐个拆解：抄什么、不抄什么

**iRightMouse（超级右键）**
- 抄：**首批模板清单**。它的功能列表就是中文用户的高频动作集，直接把前 10 名做成 Quicklet 模板
  （新建文件、复制路径、终端打开、压缩、AirDrop、彻底删除、隐藏文件、哈希、转图、剪切粘贴）。
- 抄：**「常用目录」的心智**——用户想把「跳到某个目录」变成一次点击，Quicklet 用 `open {dir}` 类模板覆盖。
- 不抄：功能越堆越多的菜单。它自己的用户评价里就有「菜单太长建议自行配置」的抱怨，
  这正是 Quicklet 用条件显示要解决的问题。

**MouseBoost**
- 抄：**脚本 + 内置动作混排**的可行性验证；专业版 ¥30 说明这个品类有付费意愿。
- 不抄：脚本只是一个「高级入口」。Quicklet 把脚本当唯一入口，把所有配置围绕它组织。

**Supercharge / Shortcutie**
- 抄：**原生长相**和克制的交互（一个菜单栏图标、一个设置窗口、不弹窗）。
- 抄：**「只在需要的时候出现」**的思路（它的动作按文件类型有条件）。
- 不抄：把能力锁在作者提供的动作里。它的用户要新动作只能去写快捷指令，链路太长。

**Finder Actions（开源）**
- 抄：**极简的配置流**（选择功能 → 排序 → 设显示位置），以及「不需要常驻窗口」的形态。
- 抄：**目录白名单**思路，扩展为 Quicklet 的路径条件。
- 不抄：用文件名/注释当元数据（对非技术用户不友好），Quicklet 用结构化配置 + GUI 编辑器。

**FileMenu Tools（Windows，最重要的对标）**
这是 Quicklet 功能模型的直接来源。它的自定义命令有这么几个属性，全部值得移植：

| FileMenu Tools 属性 | Quicklet 对应 |
| --- | --- |
| Element Types（文件扩展名通配 / 文件夹模式 / 驱动器类型） | 适用条件：选中类型 + 扩展名通配 |
| Number of elements（最少 / 最多） | 适用条件：选中数量区间 |
| Modifier Key（按住某键才显示） | 适用条件：修饰键（v1.2） |
| Arguments / Working folder | 占位符 + 工作目录字段 |
| 变量 `%FILEPATHS%` `%FILEPATH1%` | 占位符 `{paths}` `{path}` |
| 导出/导入配置 | `.quicklet` 导出导入（v1.2） |
| 按名称/类型/时间/大小排序后再执行 | 选中项排序策略（v2） |
| 多实例 / 管理员运行 | 不做（macOS 无对应概念，提权走 `sudo` 由用户自担） |

**Raycast Script Commands**
- 抄：**元数据驱动的命令定义**——一个命令的全部信息（标题、图标、说明、参数、工作目录、
  是否需要确认）都在一处声明；Quicklet 用 JSON 字段 + GUI 表单实现同一件事。
- 抄：**typed 参数**（text / dropdown / password）与「最多 3 个」的克制，作为 v2 的参数模型。
- 抄：**退出码即失败**，失败消息取 stderr 最后一行——Quicklet 的执行反馈直接采用这个约定。
- 抄：**`needsConfirmation`**，对应 Quicklet 的「执行前确认」开关。
- 不抄：Non-login shell 导致 PATH 缺失的坑（见 9.5 环境变量规格，Quicklet 主动修好 PATH）。

**Automator / 快捷指令**
- 抄：**「快速操作」的分享形态**——用户已经理解「下载一个动作 → 装进系统 → 右键可用」。
- 不抄：把配置放在另一个 App 里。Quicklet 的编辑器就是配置的唯一入口。

### 2.3 差异化定位

```
                可编程性 高
                     ▲
        Raycast      │      Quicklet
      (不在右键里)    │   (右键 + 条件 + 可分享)
                     │
   ──────────────────┼──────────────────►  上下文感知 强
                     │
      Finder Actions │   MouseBoost     iRightMouse
                     │                  (功能集合)
                可编程性 低
```

一句话：**iRightMouse 给你一堆功能，Quicklet 给你一个能长出任何功能的菜单。**

### 2.4 从竞品得到的七个必须做的功能

这一节是第 5 章功能规格的来源，评审时先看这里：

1. **适用条件**（FileMenu Tools）：类型 / 扩展名 / 数量 / 路径。
2. **占位符 + 环境变量**（FileMenu Tools、Nautilus Scripts）：脚本拿到选择的方式要稳定、够用。
3. **执行反馈**（Raycast）：退出码、stderr、失败通知，不能"点了没反应"。
4. **参数输入**（Raycast）：v1 单行，v2 多参数 typed。
5. **模板库**（iRightMouse）：让不会写脚本的人第一天就有获得感。
6. **导出/导入**（FileMenu Tools、快捷指令）：命令能离开这台机器。
7. **克制的默认外观**（Supercharge）：菜单栏一个图标，一个设置窗口。

### 3.2 关键场景走查

**场景 A：首次使用（目标 ≤ 3 分钟）**

1. 拖 App 到「应用程序」→ 打开 → 菜单栏出现图标，同时弹出设置窗口。
2. 设置窗口显示「3 步开始」引导：授权完全磁盘访问 → 启用 Finder 扩展 → 试一条模板。
3. 用户点「授权」跳系统设置，回来点「已完成，重新检测」。
4. 用户在 Finder 右键 → 看到 `Quicklet › 模板 › 新建文件…` → 点击 → 输入 `notes.md` → 文件出现并选中。
5. 完成。

**场景 B：日常使用（每次 2 秒内）**

1. 选中 3 个 `.png` → 右键。
2. 第一层出现「压缩为 zip」，`Quicklet` 子菜单里有「图片 › 转 WebP」。
3. 「转 WebP」点下去 → 菜单栏图标转圈 → 完成后通知「已转换 3 个文件」。
4. 全部命令都不匹配时，第一层只出现 `Quicklet` 一项（不显示空的分组）。

**场景 C：导入别人的命令**

1. 双击 `team-pack.quicklet` → Quicklet 打开「导入预览」。
2. 预览列出 5 条命令、每条的名称/分组/脚本文本、以及风险标记（有 1 条含 `rm -rf`）。
3. 默认全部**不勾选**，用户逐条勾选；含风险的命令额外要求勾「我知道它在做什么」。
4. 确认后导入为**禁用状态**，用户在列表里逐条启用。

**场景 D：出错**

1. 命令执行 `git status` 在非仓库目录 → exit 128 + stderr。
2. 菜单栏图标短暂变化 → 通知中心：「在终端中打开失败」+ stderr 首行。
3. 用户点通知 → 打开「诊断与日志」，定位到那条记录（含展开后的完整脚本）。

## 4. 产品结构与概念模型

### 4.1 概念模型

```
Command（命令）── 一条菜单项
├── 身份：id(UUID) · name · icon(SF Symbol) · enabled
├── 行为：script · shell · workingDirectory · timeoutSeconds
├── 输入：prompt（v1 单行输入）→ parameters（v2 多参数）
├── 位置：placement { topLevel | group([String]) } · order
├── 条件：conditions { selection · extensions · itemCount · paths · modifierKey }
└── 反馈：notifyOnFailure · showOutputWindow
```

四个关键词：

- **Command** 是唯一实体。分组不是实体，只是命令上的一个路径（`group: ["开发","Git"]`），
  同名路径自动合并成同一个菜单。
- **Placement** 只有两种：右键第一层，或 `Quicklet` 根菜单下的 0–2 层分组。
  `Quicklet` 根菜单名固定、不可删。
- **Conditions** 是"何时可见"的谓词集合，全部满足才显示（AND 语义）。
- **Preset** 是预填好的 Command 模板，创建后就是普通 Command，不与模板保持关联
  （避免"改模板影响所有人"的隐式耦合）。

### 4.2 菜单结构（唯一合法形态）

```
Finder 右键
├── [第一层命令 A]                 ← placement = topLevel
├── [第一层命令 B]
├── ──────────
├── Quicklet                      ← 固定根菜单，永远存在
│   ├── [根下命令]                 ← group = [] 但 placement = root（v1.1 支持）
│   ├── 开发                       ← group = ["开发"]
│   │   ├── [命令]
│   │   └── Git                    ← group = ["开发","Git"]
│   │       └── [命令]
│   └── 文件
│       └── [命令]
```

规则（全部为硬约束，实现时不可放宽）：

| 编号 | 规则 |
| --- | --- |
| M-1 | `Quicklet` 根菜单名称固定为 `Quicklet`，不可改名、不可删除、不可隐藏 |
| M-2 | 分组最多两层；配置里更深的路径截断到两层，不报错 |
| M-3 | 分组不是实体，由命令的 `group` 路径隐式创建；空分组（没有可见命令）整体不显示 |
| M-4 | 同一层级内的顺序：`order` 升序，未设 `order` 的按名称本地化排序；分组始终排在命令之后 |
| M-5 | 命令与分组之间、第一层命令与 `Quicklet` 之间插入分隔线 |

### F5 适用条件（核心待实现） ⬜

**目标**：菜单只在「选中的东西符合条件」时出现。这是与功能集合型工具的分水岭。

**条件字段**

| 字段 | 类型 | 语义 | 默认 |
| --- | --- | --- | --- |
| `selection` | enum | `any` / `file` / `folder` / `mixed` / `none` | `any` |
| `extensions` | [String] | 扩展名，小写，支持 `*`；空数组＝不限 | `[]` |
| `minItems` | Int | 最少选中数（含） | `0` |
| `maxItems` | Int | 最多选中数（含）；`0`＝不限 | `0` |
| `pathPrefixes` | [String] | 选中项路径必须以其中之一开头（支持 `~`）；空＝不限 | `[]` |
| `excludePathPrefixes` | [String] | 命中即不显示（优先级高于 include） | `[]` |
| `modifierKey` | enum | `none` / `option` / `control` / `shift`（按住才显示） | `none` |

**语义**

- 多个字段之间是 **AND**；同一字段内多个值是 **OR**。
- `selection = none` 表示「空白处右键（无选中）」；此时 `dir` 是当前浏览的文件夹。
- 选中项类型不一致时：全部文件＝`file`，全部文件夹＝`folder`，混合＝`mixed`。
  条件写 `file` 时 `mixed` **不匹配**（宁可少显示）。
- 路径前缀比较基于标准化后的绝对路径（`~` 展开、去掉末尾 `/`），大小写敏感
  （macOS 默认文件系统大小写不敏感，但 `/Volumes` 外置盘可能敏感，按字面比较更可预期）。
- `modifierKey` 只在菜单构建时读取当前修饰键状态；不满足则该命令不出现。

**规格**

| 编号 | 要求 |
| --- | --- |
| F5-1 | 编辑器「显示条件」区块，默认折叠为一行摘要：`选中文件夹 · 1 项 · 任意路径` |
| F5-2 | 扩展名输入支持逗号分隔与标签式输入，自动补 `.`、转小写 |
| F5-3 | 提供「用当前 Finder 选择测试」按钮（v1.1 可只做静态提示文案） |
| F5-4 | 条件不匹配的命令在设置列表中显示原因（灰色小字：`当前不匹配：需要选中图片`） |
| F5-5 | 条件解析逻辑放在 `Shared/CommandFilter.swift`，纯函数、可单测、不依赖 Finder |
| F5-6 | 配置里非法值（未知 enum、负数）回退默认并写日志，不让整个配置解码失败 |

**验收**

- E1：命令条件 `selection=folder`，选中 2 个文件时该命令不出现；选中 1 个文件夹时出现。
- E2：条件 `extensions=["png","jpg"]`，选中 `a.png` 出现；选中 `a.txt` 不出现；选中 `a.png`+`b.txt` 不出现（不是全匹配）。
- E3：条件 `minItems=2, maxItems=3`，1/4/5 项时不出现，2/3 项时出现。
- E4：条件 `pathPrefixes=["~/work"]`，在 `~/work/x` 出现，在 `~/tmp` 不出现。
- E5：`selection=none` 的命令只在该文件夹空白处右键时出现。
- E6：`modifierKey=option`，不按 ⌥ 不出现，按住 ⌥ 出现。
- E7：单测覆盖上述 6 条（`CommandFilterTests`）。

- J3：把 App 放到 `~/Desktop` 运行 → 权限页显示「当前不在应用程序文件夹」警示。

### F11 诊断与崩溃收集 ✅

**目标**：出问题时用户能自证，不必靠猜。

**规格（已实现，本文档固化为契约）**

| 编号 | 要求 |
| --- | --- |
| F11-1 | 滚动日志 `Logs/quicklet.log`，超过 512 KB 轮转为 `.1` |
| F11-2 | 每类进程独立标记：`[Quicklet]` / `[QuickletFinder]` |
| F11-3 | 每次执行记录：命令名、路径数、展开后的完整脚本、退出码、stderr（截断 2000 字） |
| F11-4 | 崩溃捕获：未捕获异常 + `SIGABRT/SEGV/BUS/ILL/FPE/TRAP`，写 `Crashes/crash-*.txt`（含回溯） |
| F11-5 | 崩溃处理里只做 `write` / `unlink` / `backtrace`，之后恢复 `SIG_DFL`，不拦截系统 `.ips` 报告 |
| F11-6 | 会话标记 `Logs/session.active`，非正常退出时下次启动提示「上次异常退出」 |
| F11-7 | 日志页可「复制全部日志」「在 Finder 中显示」「清空日志」（清空前确认） |
| F11-8 | 提供系统 `.ips` 报告目录入口 |
| F11-9 | **不记录 `{input}` 的原文**（可能是密码/密钥）——v1.1 补齐（当前会记录展开后脚本） |

**验收**

- K1：`kill -SEGV <pid>` → `Crashes/` 出现报告，且系统 `.ips` 仍生成。
- K2：连续运行超过 512 KB → 生成 `.1`，新日志从空开始。
- K3：设置输入型命令的输入为 `secret123` → 日志中不出现该字符串（F11-9 完成后）。

## 7. 数据模型与迁移

### 7.1 存储位置

```
~/Library/Group Containers/group.com.ice.quicklet/
├── commands.json          # 命令库（唯一真相源）
```

`~/Library/Application Support/Quicklet/`，逻辑与结构一致。

### 7.2 Schema v2（v1.1 起）

```json
{
  "schemaVersion": 2,
  "commands": [
    {
      "id": "3F2504E0-4F89-11D3-9A0C-0305E82C3301",
      "name": "在终端中打开",
      "icon": "terminal",
      "script": "open -a Terminal {dir}",
      "enabled": true,
      "placement": "group",
      "group": ["开发"],
      "order": 10,
      "conditions": {
        "selection": "folder",
        "extensions": [],
        "minItems": 1,
        "maxItems": 0,
        "pathPrefixes": [],
        "excludePathPrefixes": [],
        "modifierKey": "none"
      },
      "workingDirectory": "",
      "shell": "/bin/zsh",
      "timeoutSeconds": 0,
      "showOutputWindow": false,
      "confirmBeforeRun": false,
      "prompt": {
        "title": "新建文件",
        "placeholder": "文件名，例如 notes.md"
      },
      "parameters": []
    }
  ]
}
```

### 7.3 兼容与迁移规则

| 规则 | 说明 |
| --- | --- |
| R-1 | 读到**裸数组**（v1 格式）→ 视为 `schemaVersion: 1`，逐条补默认值 |
| R-2 | 缺字段一律补默认（`group: []`、`conditions` 全默认、`placement` 由 `group` 推导） |
| R-3 | 未知字段保留（写回时不丢），为未来降级留余地 |
| R-4 | 只有 `schemaVersion` 比当前**大**时才拒绝写入，并提示「配置来自更新版本」 |
| R-5 | 迁移在内存中完成，首次保存时写新格式，同时留 `commands.bak.json` |
| R-6 | 单个命令解码失败 → 跳过该条并记日志，不让整个文件失败（现状会整体清空，v1.1 修） |

### 7.4 `.quicklet` 交换格式

见 F7。与 `commands.json` 的区别：无 `id`、无 `enabled`（导入即禁用）、带来源元数据。

## 8. 技术架构与约束

### 8.1 现有链路

```
Finder 右键
  └─ QuickletFinder.appex（沙箱，不能 spawn 子进程）
       ├─ 读 commands.json（App Group）
       ├─ 构建 MenuTree → NSMenu
       └─ quicklet://run?id=<UUID>&path=…（URL scheme 传话）
            └─ Quicklet.app（非沙箱、常驻后台，Dock + 菜单栏双入口）
                 ├─ 校验 id → 重新读盘
                 ├─ 需要输入 → NSAlert 取一行
                 └─ /bin/zsh 执行 → 日志
```

**两个不可抗力**（决定了整个架构，不要在实现中试图绕过）：

1. Finder Sync 扩展被系统强制运行在 App Sandbox 里。
2. 沙箱内 `Process` 启动子进程会直接失败（不是权限问题，是策略）。

因此「执行」永远只能发生在主 App。这是本产品的架构第一性原理。

### 8.2 演进方向

| 目标 | 方案 | 触发条件 |
| --- | --- | --- |
| 消除 URL scheme 的多副本问题 | Mach service + 反向 XPC（appex 侧声明 `mach-lookup` 临时例外） | v2.0 评估，若签名策略不允许则保留现状 |
| 菜单更快 | 扩展侧内存缓存 + `CFNotificationCenterDarwin` 变更广播 | 命令数 > 100 或 P95 > 120 ms |
| 命令执行不阻塞 | 串行 `OperationQueue`（maxConcurrent = 1/命令） | v1.1 |
| 主 App 常驻内存 | 现状约 40–60 MB；> 80 MB 时排查 SwiftUI 窗口是否被提前创建 | 持续观察 |
| 分发 | Developer ID + 公证 + Sparkle | v2.0 |

### 8.3 工程约束（写代码时必须遵守）

1. **构建**：`scripts/build.sh` 是唯一可信安装路径。Xcode 直接 ⌘R 会在 App Groups 上要求
   provisioning profile，属已知限制。
2. **签名**：ad-hoc 构建 + 本机开发证书重签；两份独立 entitlements
   （app 仅 App Groups；appex 沙箱 + App Groups）。
3. **编译**：需要 `OTHER_SWIFT_FLAGS='$(inherited) -disable-sandbox'`（宿主沙箱挡编译器嵌套沙箱）。
4. **版本号单一来源**：`project.yml` 的 `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION`。
5. **共享代码**：`Shared/` 同时编入两个 target，不得 import AppKit 之外的 UI 框架；
   纯逻辑（条件、菜单树、占位符、版本比较）必须能脱离 Finder 单测。
6. **注释语言**：英文（用户明确要求）。
7. **不引入第三方依赖**：App 本身零依赖；测试可用 XCTest。

### 9.1 菜单文案

| 场景 | 文案 |
| --- | --- |
| 根菜单 | `Quicklet` |
| 根菜单为空 | `在设置中添加分组命令`（禁用态） |

| 执行中 | 菜单项右侧无变化（图标状态在菜单栏） |
| 失败通知标题 | `{命令名} 失败` |
| 失败通知正文 | stderr 最后一行，> 120 字截断加 `…` |
| 完成通知标题 | `{命令名} 已完成` |
| 超时通知正文 | `超时（{n}s），已终止` |

### 9.2 命令编辑（内联，已实现）

**单击选中即编辑**：右侧详情栏就是编辑器，没有弹窗。所有修改通过命令库的
300 ms 防抖自动落盘，没有「保存」按钮；「+」直接生成一条**禁用的草稿命令**
（禁用草稿不会出现在菜单里），同样在详情栏编辑。

字段顺序（自上而下）：

1. 名称（无框大字输入）+ 右侧「已启用」开关
2. 图标（SF Symbol 输入 + 常用图标快捷选择）
3. 菜单位置（分段控件：右键第一层 / Quicklet 菜单内 → 一级分组 / 二级分组）
4. Shell 命令模板（等宽、可换行、浅底边框编辑区；下方占位符标签速查）
5. 执行前输入（标题 / 占位提示）

分组字段是本地状态，选中项切换（`onChange(command.id)`）时重新同步；
两档分组实时写回 `group` 路径数组，留空一级分组时自动回退到第一层。

打开页面时自动选中第一条命令，右侧不会出现空面板（空库时除外）。

### 9.3 条件区块交互

```
┌ 显示条件 ────────────────────────── 摘要：选中文件夹 · 1 项 ─┐
│ 选中类型   ( 任意 )( 文件 )( 文件夹 )( 混合 )( 空白处 )      │
│ 扩展名     [ png ] [ jpg ] [ + ]                              │
│ 选中数量   最少 [ 1 ]   最多 [ 0 = 不限 ]                     │
│ 仅在这些位置  [ ~/work ] [ + ]        排除  [ + ]             │
│ 修饰键     ( 不需要 )( ⌥ )( ⌃ )( ⇧ )                          │
│                                              [ 重置为默认 ]   │
└───────────────────────────────────────────────────────────────┘
```

要点：

- 「选中类型」用分段控件，五档一屏可见，不留学习成本。
- 扩展名输入后按回车变成标签；标签可点 × 删除；输入 `*` 表示全部。
- 数量两个字段并排，`0` 在「最多」里显式标注为「不限」。
- 路径用标签 + 目录选择器（不要手打长路径）。
- 摘要行始终反映当前设置，用于列表页二次确认。

### 9.4 空状态与错误态

| 位置 | 空状态 | 错误态 |
| --- | --- | --- |
| 命令列表 | 「还没有自定义命令，点 + 新建一个」+「从模板开始」 | — |
| 命令详情（未选中） | 图标 + 「选择左侧命令，或点 + 新建」+ 启用扩展提示 | — |
| 权限页 | — | 未授权：橙色提示 + 跳转按钮 |
| 诊断页 | 「暂无日志」 | 上次异常退出：红色横幅 |
| 导入预览 | — | 无效文件：「这不是有效的 Quicklet 命令文件」 |

### 9.5 执行环境规格

| 项 | 值 |
| --- | --- |
| Shell | `/bin/zsh -lc`（登录 shell，读取用户 PATH 与 rc） |
| 工作目录 | `workingDirectory`（支持 `~` 与占位符）→ 空则 `{dir}` → 再空则 `$HOME` |
| stdout | 默认丢弃；开启「显示输出窗口」时捕获 |
| stderr | 始终捕获（上限 64 KB），用于失败文案与日志 |
| 注入环境变量 | `QUICKLET_VERSION` `QUICKLET_COUNT` `QUICKLET_DIR` `QUICKLET_CWD` `QUICKLET_PATHS`（换行分隔） |
| 超时 | `timeoutSeconds`（0 = 不限）；超时后 `killpg(SIGTERM)`，5 秒后 `SIGKILL` |
| 并发 | 同一命令串行；不同命令最多并行 3 个 |
| 编码 | UTF-8；`LANG` 沿用系统 |

> 环境变量与占位符的分工：占位符用于**拼命令**（带转义），环境变量用于**脚本内部读取**
> （不经过 shell 解析，更安全）。两者同时提供，文档里要讲清各自适用场景。

### 9.6 可访问性

- 所有设置窗口控件有 VoiceOver 标签；图标按钮必须有 `help` 文案。
- 菜单项名称即无障碍标题，不依赖图标传达含义。
- 支持键盘全流程：列表 ↑↓ 移动、`⌘N` 新建、`⌫` 删除（带确认）、`⌘↩` 保存。
- 尊重「减少动态效果」（不做弹入动画）。

## 11. 安全与隐私

### 11.1 威胁模型

Quicklet 的本质是「一个能执行任意脚本的入口」。威胁不在产品本身，而在：

| 威胁 | 场景 | 缓解 |
| --- | --- | --- |
| T1 恶意命令包 | 用户从群里下载 `.quicklet`，里面藏 `curl … \| sh` | 导入预览展示全文 + 默认禁用 + 风险标记 + 默认不勾选（F7） |
| T2 误触破坏性命令 | 自己写的 `rm -rf` 随手点了 | 危险模式警示 + 可选「执行前确认」（F13） |
| T3 输入内容泄露 | 输入的是密码，被写进日志 | 默认不记录 `{input}`（F11-9） |
| T4 更新劫持 | 中间人替换更新包 | HTTPS + 校验版本与包结构 + 原子替换 + 失败回滚（F12-5） |
| T5 权限扩散 | 用户为省事给了 FDA | 说明「为什么需要」，不主动索取；无 FDA 也能用（只是会逐次询问） |
| T6 日志泄露 | 日志包含敏感路径 | 日志只在本机 App Group；导出日志需用户主动操作 |

### 11.2 风险模式清单（导入时静态检查）

命中即标黄（不阻止，但要勾选确认）：

```
sudo                chmod -R 777      chown -R
curl … | sh         wget … | sh       eval $(
> /dev/disk*        dd if=            mkfs
```

实现：正则匹配 + 关键 token 分词，宁可误报不可漏报；命中项在预览里高亮该行。

### 11.3 隐私承诺

### 11.4 分发策略

## 12. 度量

不做服务端统计，用本地可选统计回答两个问题：**有没有人用**、**哪一步卡住**。

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 激活率 | 安装后 7 天内至少执行过 1 条命令 | > 70% |
| 留存 | 第 2 周仍有执行记录 | > 50% |
| 命令数中位数 | 每个用户启用的命令数 | 5–8 条（少于 3 说明模板不够好用） |
| 命令失败率 | 非 0 退出 / 总执行 | < 2%（高则说明模板前提检查不足） |
| 条件命中率 | 有命令因条件被隐藏的菜单占比 | 30–60%（过低说明没人用条件，过高说明条件太严） |
| 首次配置耗时 | 首启到保存第一条命令 | < 3 分钟 |

存储：`Logs/metrics.json`（只累加计数，不含内容），设置页可一键清空与关闭。

### 14.2 模板脚本清单

| 名称 | 脚本 |
| --- | --- |
| 新建文件… | `test -e {dir}/{input} && { echo "同名文件已存在，未覆盖"; exit 1; }; touch {dir}/{input}; open -R {dir}/{input}` |
| 新建文件夹… | `mkdir -p {dir}/{input} && open -R {dir}/{input}` |
| 复制路径 | `printf '%s\n' {paths} \| pbcopy` |
| 复制文件名 | `for p in "$@"; do basename "$p"; done \| pbcopy`（配合 `{paths}` 作为参数） |
| 在终端中打开 | `open -a Terminal {dir}` |
| 用 VS Code 打开 | `open -a "Visual Studio Code" {paths}` |
| 压缩为 zip | `cd {dir} && zip -rq "{input}.zip" {paths} && open -R "{dir}/{input}.zip"` |
| 计算 SHA-256 | `shasum -a 256 {paths} \| pbcopy && echo "已复制"` |
| 图片转 WebP | `command -v cwebp >/dev/null \|\| { echo "请先安装 cwebp：brew install webp"; exit 1; }; for p in {paths}; do cwebp -quiet "$p" -o "${p%.*}.webp"; done` |
| 显示/隐藏隐藏文件 | `defaults read com.apple.finder AppleShowAllFiles >/dev/null 2>&1 && v=$(defaults read com.apple.finder AppleShowAllFiles) \|\| v=NO; [ "$v" = "YES" ] && defaults write com.apple.finder AppleShowAllFiles -bool NO \|\| defaults write com.apple.finder AppleShowAllFiles -bool YES; killall Finder` |
| 移到废纸篓 | `osascript -e 'tell application "Finder" to delete every item of (POSIX file "{dir}" as alias) whose name is in …'`（v1.2 实现时改为逐个 `osascript` 调用） |

### 14.3 术语

| 术语 | 定义 |
| --- | --- |
| 命令（Command） | 一条右键菜单项及其脚本、位置、条件 |
| 占位符（Placeholder） | 脚本里被替换为路径/输入的 `{…}` token |
| 条件（Condition） | 决定命令是否显示的谓词集合，AND 语义 |
| 位置（Placement） | `topLevel` / `root` / `group` 三档 |
| 传话（Hand-off） | 扩展通过 URL 把命令 id 与路径交给主 App 的过程 |
| 模板（Preset） | 预填内容的命令草稿，创建后与模板无关 |
| 命令包（`.quicklet`） | 可导入导出的命令交换文件 |
